Ephemeral AES-256-GCM & 96-Bit Nonce

For every message, browser RAM generates a 256-bit symmetric key (K_msg) and 96-bit random IV (N). Plaintext never touches the network.

// 1. Generate ephemeral key & 96-bit random nonce K_msg = crypto.subtle.generateKey({name:'AES-GCM', length:256}) IV = crypto.getRandomValues(new Uint8Array(12)) // 96-bit IV C_body || Tag = AES-GCM_{K_msg}(Plaintext, IV)

If you send “Good morning” daily with the same key, outside snoops spot repeated parcel sizes and patterns. Mixing random colored glitter into the wax seal makes every single parcel look completely unique and unpredictable to outside couriers.

AEAD Guarantee: Authenticated encryption with a 128-bit MAC tag. Decryption immediately aborts if even 1 bit is altered in transit or in the database.

// 2. Encapsulate symmetric key for both parties K_recipient = RSA-OAEP_{Pub_recipient}(K_msg) K_sender = RSA-OAEP_{Pub_sender}(K_msg) Payload = "E2EE:" + JSON({ v:1, iv: IV, key: K_recipient, ct: C_body })

PBKDF2-HMAC-SHA256 & Runtime Isolation

PBKDF2-HMAC-SHA256: A cryptographic function that transforms human student passwords into uniform 256-bit AES keys by intentionally looping 600,000 times through HMAC-SHA256, making GPU dictionary cracking mathematically unfeasible. Runtime Isolation: WebCrypto memory locking (extractable: false) that prevents rogue scripts or browser extensions from exporting raw private keys from RAM.

What is PBKDF2? (600k Rounds)

Stretches a password into a 256-bit AES wrapping key using 16-byte random salt:

K_wrap = PBKDF2( password = StudentPassword, salt = RandomBytes(16), iterations = 600,000, hash = 'SHA-256' )
Analogy · High Work Factor
Vault Wheel in Honey
Turning the wheel once takes an authorized student 0.2s. But a hacker testing 100M guesses/sec must crank through syrup 600,000 times per guess, turning minutes into decades.

OWASP Alignment: Neutralizes GPU/FPGA rainbow-table and offline dictionary attacks.

What is Salt & Wrapping?

The RSA private key JWK is encrypted with AES-256-GCM using K_wrap into a v2 bundle:

Bundle = { v: 2, iter: 600000, salt: Base64(salt), iv: Base64(iv), ct: Base64(encryptedJWK) }

Secret Spices in Dough
If two students pick the same password “Student@123”, 16-byte salt adds unique spices before baking. Alice’s and Bob’s bundles look totally distinct, neutralizing shared tables.

Auto-Migration: 100k bundles decrypt seamlessly and auto-rewrap to 600k on unlock.

What is Runtime Isolation?

Protects private key material in execution context and handles password resets cleanly:

Message Encryption (AES-256-GCM) & Key Encapsulation (RSA-OAEP)

1. Message Encryption — AES-256-GCM

Stands For: Advanced Encryption Standard (256-Bit) in Galois/Counter Mode · NIST SP 800-38D

What it is & does: Symmetric authenticated encryption for chat payloads. It transforms plaintext into ciphertext while calculating a 128-bit authentication tag. Decryption immediately aborts if even 1 bit is modified in transit or database.

// 1. Generate ephemeral 256-bit symmetric key & 96-bit CSPRNG IV K_msg = crypto.subtle.generateKey({name:'AES-GCM', length:256}) IV = crypto.getRandomValues(new Uint8Array(12)) // 96-bit Nonce // 2. Encrypt & generate 128-bit GHASH authentication tag C_body || Tag_128 = AES_GCM_Encrypt(K_msg, IV, Plaintext, AAD) // Integrity Check: If Tag fails -> throws OperationError!
Real-Life Analogy · Tamper Seal
The Tamper-Evident Bank Bag with Glitter Wax
You lock cash in a steel pouch. You stamp the seal with wax mixed with random colored glitter (the 96-bit IV) and an embossed tamper seal (the 128-bit tag). If a courier peeks inside, the glitter shifts and the seal fractures—tampering is spotted instantly.

Security Guarantee: Unconditional payload confidentiality ($2^{256}$ keyspace) + mathematical AEAD tamper resistance.

2. Key Encapsulation — RSA-OAEP

Stands For: Rivest-Shamir-Adleman with Optimal Asymmetric Encryption Padding · RFC 8017

What it is & does: Asymmetrically wraps the ephemeral 256-bit AES message key so it travels safely over public networks. Dual-envelope encapsulation wraps the key twice: once for Bob's inbox and once for Alice's sent box.

// 1. OAEP randomized padding with SHA-256 mask generation Pad_Key = OAEP_Encode(K_msg, Seed=Random, Hash=SHA-256, MGF1) // 2. Dual asymmetric wrapping (modulus 2048-bit, e=65537) Enc_Bob = (Pad_Key)^e mod N_Bob // Wrapped for Bob's Private Key Enc_Alice = (Pad_Key)^e mod N_Alice // Wrapped for Alice's Sent History Payload = "E2EE:" + JSON({ v:1, iv: IV, key: Enc_Bob, ct: C_body })
Real-Life Analogy · Public Drop Box
The Community Mail Drop Box with Private Keyhole
Anyone can drop an envelope through your street mail slot (public key). But once it drops inside, nobody—not even the mailman—can reach inside to pull it out. Only you, holding your private brass key (private key), can open the back door to read it.

Security Guarantee: IND-CCA2 security against chosen-ciphertext attacks; server never learns the AES session key.

3. Key Derivation — PBKDF2-HMAC-SHA256

Stands For: Password-Based Key Derivation Function 2 (HMAC-SHA256) · RFC 8018 / OWASP '24

What it is & does: Derives a military-grade 256-bit AES key from the user's master password to wrap their private RSA key in client storage. Intentionally computational-heavy to render GPU/ASIC password cracking mathematically unfeasible.

// 1. Generate 16-byte random salt (prevents rainbow tables) Salt = crypto.getRandomValues(new Uint8Array(16)) // 2. Chained PRF iterations (OWASP 2024 recommended 600,000 rounds) K_derived = crypto.subtle.deriveKey({ name: 'PBKDF2', salt: Salt, iterations: 600000, hash: 'SHA-256' }, PasswordKey, { name: 'AES-GCM', length: 256 }, false, ['wrapKey']) Enc_PrivKey = AES_GCM_Wrap(K_derived, IV, User_RSA_PrivateKey)
Real-Life Analogy · Vault Friction
The Bank Vault Hand-Crank in Thick Molasses
To open your locker, you must rotate a heavy iron wheel 600,000 times through a vat of thick honey. For you, turning it once takes 180 ms—a minor blink. But if a thief uses a high-speed drill to test millions of keys, the motor burns out instantly in the sticky syrup.

4. Second Factor (2FA) — RFC 6238 TOTP

Stands For: Request for Comments 6238 Time-Based One-Time Password · RFC 6238 / RFC 4226

What it is & does: Generates synchronized 6-digit offline identity codes refreshed every 30 seconds without SMS. Monotonic database fencing rejects expired or already-used codes, completely defeating replay attacks.

// 1. Calculate 30-second epoch time step counter (X = 30s) T = Math.floor(Date.now() / 1000 / 30) Hash = HMAC_SHA1(Key: base32_decode(Seed_160bit), Message: uint64(T)) // 2. Dynamic Truncation to 31-bit integer & modulo reduction Offset = Hash[19] & 0x0f Binary = ((Hash[Offset] & 0x7f) << 24 | (Hash[Offset+1] & 0xff) << 16 | (Hash[Offset+2] & 0xff) << 8 | (Hash[Offset+3] & 0xff)) OTP = (Binary % 1000000).toString().padStart(6, '0') // 6 digits

Synchronized Wristwatches & Radio Codebook
You and your commander each carry an identical pocket math cipher book and synchronize your wristwatches down to the second. At 10:00:00 AM, both watches point to the exact same page number, generating 582914. At 10:00:30 AM, the second hand ticks and that code dies forever.

Security Guarantee: Out-of-band identity attestation; monotonic counter strictly prevents replay attacks.

7. Anti-MITM Verification — Iterative SHA-256

Stands For: Iterative (5,000 Rounds) Secure Hash Algorithm 256-Bit · NIST FIPS 180-4

What it is & does: Calculates a deterministic 60-digit pairwise identity fingerprint (“Safety Number”) between Alice and Bob. Allows parties to verify out-of-band that no Man-in-the-Middle (MITM) adversary or rogue server has intercepted the channel or swapped keys.

// 1. Lexicographically sort Alice & Bob 2048-bit RSA public keys Keys_Sorted = [Alice_PubKey, Bob_PubKey].sort().join(":") // 2. 5,000 recursive SHA-256 hashing iterations Digest = SHA-256(Keys_Sorted) for round in 1..5000: Digest = SHA-256(Digest + Keys_Sorted) // 3. Chunk into twelve 5-digit decimal blocks -> 60-digit Safety Number SafetyNumber = ChunkDigits(Digest, blocks=12, digits_per_block=5) // Displays: 48291 19482 94810 59284 ... (Guarantees zero MITM tampering)

Signal Protocol: Double Ratchet, X3DH & Sealed Sender

Designed by Open Whisper Systems (Moxie Marlinspike & Trevor Perrin), the Signal Protocol is the peer-reviewed gold standard for end-to-end encryption. It ensures keys constantly evolve with every single message, healing sessions automatically even after a temporary device compromise.

Extended Triple DH (X3DH)

Asynchronous key agreement when recipient is offline or in airplane mode:

// 1. Fetch Bob's pre-published public keys DH1 = DH(IdentityKey_A, SignedPrekey_B) DH2 = DH(EphemeralKey_A, IdentityKey_B) DH3 = DH(EphemeralKey_A, SignedPrekey_B) SK = HKDF(DH1 || DH2 || DH3 || DH4)
Analogy · X3DH
Pre-Cut Hotel Drop Keys
Bob leaves pre-cut 1-time keys on the server before sleeping. Alice takes one key, locks her secret envelope, and walks away. Bob decrypts when he wakes up. They never meet in person.

Guarantee: Mutual authentication & forward secrecy without requiring both parties online.

The Double Ratchet Algorithm

Continuous cryptographic key evolution combining DH and Symmetric KDF ratchets:

// Symmetric Ratchet: Every message advances hash chain ChainKey_i+1, MessageKey_i = KDF_chain(ChainKey_i) // DH Ratchet: Every roundtrip reply advances master root RootKey_next, ChainKey_new = KDF_root(RootKey, DH_ephemeral)
Analogy · Self-Healing
Burning Mechanical Gear Chain
Every message turns the gear; the old tooth breaks off and burns. Stealing a key today cannot unlock yesterday's messages (Forward Secrecy). And the next reply heals into a fresh secret.

PCS Guarantee: Post-compromise security guarantees session healing after malware infection.

Sealed Sender Architecture

Eliminates sender identity metadata from routing envelopes:

// Normal app: Server logs [Alice -> Bob at 10:42 PM] // Signal Sealed Sender: Server routes blind: Envelope = { delivery_token: BobDeliveryToken, inner_cipher: EncryptedForBob({ sender: Alice, body: Msg }) } // Server NEVER knows who sent the message!

What Happens When FBI / CIA Subpoenas Signal’s Servers?

In 2016 and 2021, the US Department of Justice and the FBI served sweeping Grand Jury subpoenas on Signal. The legal outcome demonstrated the ultimate power of zero-knowledge engineering: the government demanded everything, and walked away empty-handed.
